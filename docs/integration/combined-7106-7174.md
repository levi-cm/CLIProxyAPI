## Deployment constraint

The user's replacement global AGENTS instructions require a verified zero-downtime
handoff and preservation of HTTP streams and WebSocket sessions before a production
upgrade. The current idle controller closes admission, stops the old writer, and
starts the candidate; its own README explicitly permits a brief maintenance
interruption. Waiting for idle does not provide a zero-downtime listener handoff.

The old waiting watcher for the earlier image was stopped while the original
serving router remained running. A combined image and isolated preparation can be
staged, but this maintenance controller must not be armed under the current
zero-downtime requirement. The live application remains unchanged until that
constraint is satisfied or the user explicitly changes the requirement.
